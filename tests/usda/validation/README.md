# USD validation fixtures

Synthetic `.usda` fixtures for the AOUSD Core semantic validator
(`src/usd-validation.{hh,cc}`, exercised by `tests/unit/unit-usd-validation.cc`
and the `tusdcat --validate` / `--validate-all` CLI).

## Layout

- `valid/` — scenes that must produce **no issues**.
  - `clean.usda` — passes every rule group (core + geom + shade).
  - `gated-composition.usda` — proves locality-dependent rules do not fire on
    prims that carry composition arcs (no false positives).
- `invalid/` — hand-written; each file trips a specific rule.
- `generated/` — produced by `gen_validation_fixtures.py` from the canonical
  schema (do not edit by hand; regenerate instead).

The canonical schema lives at `src/usd-preview-surface-schema.json` and is the
**single source of truth**: it drives both these fixtures *and* the validator's
input-type table (`src/usd-preview-surface-inputs.inc`, generated by
`scripts/gen-usd-preview-surface-inputs.py`).

## Self-checking markers

Every fixture embeds machine-readable expectations as `#` comment lines just
after the `#usda 1.0` header:

```
#usda 1.0
# EXPECT-OK                  # the file must produce no validation issues
# EXPECT: <rule_id>          # the file must report this rule (repeatable)
```

`run-validation-suite.py` reads these markers, runs `tusdcat --validate-all`,
and checks the reported `[rule_id]` tokens against them. For fixtures whose
expected rules are all opt-in (`geom.*` / `shade.*`), it also runs core-only
`--validate` and asserts nothing is reported — verifying the groups are opt-in.
The suite runs in CTest as `validation-suite-test`.

```bash
python3 tests/usda/validation/run-validation-suite.py --app ./build/tusdcat
```

## Rule groups

`core` runs by default. `geom` and `shade` are opt-in (`--validate-all`, or
`groups: ["all"]` via the `usd_validate` MCP tool), because they are
warning-heavy and composition-sensitive.

| Fixture | Group | Expected rule_id | Severity |
|---------|-------|------------------|----------|
| `invalid/missing-default-prim.usda` | core | `core.layer.defaultPrim` | error |
| `invalid/bad-meters-per-unit.usda` | core | `core.layer.metersPerUnit` | error |
| `invalid/bad-timecodes-per-second.usda` | core | `core.layer.timeCodesPerSecond` | error |
| `invalid/bad-frames-per-second.usda` | core | `core.layer.framesPerSecond` | error |
| `invalid/bad-timecode-range.usda` | core | `core.layer.timeCodeRange` | warning |
| `invalid/bad-xformop-order.usda` | core | `core.xformOp.order` | error |
| `invalid/colorspace-unknown.usda` | core | `core.schema.ColorSpaceAPI.name` | error |
| `invalid/collection-bad-expansion.usda` | core | `core.schema.CollectionAPI.expansionRule` | error |
| `invalid/multi-violation.usda` | core+geom | (three rules at once) | mixed |
| `invalid/nested-gprim.usda` | geom | `geom.encapsulation.nestedGprim` | warning |
| `invalid/shader-bad-parent.usda` | shade | `shade.encapsulation.shaderParent` | warning |
| `invalid/material-binding-as-attr.usda` | shade | `shade.material.binding` | error |
| `invalid/material-binding-missing-api.usda` | shade | `shade.material.bindingAPI` | warning |
| `invalid/preview-bad-input-type.usda` | shade | `shade.preview.inputType` | warning |
| `invalid/preview-unknown-input.usda` | shade | `shade.preview.unknownInput` | warning |
| `generated/usdpreviewsurface-badtype.usda` | shade | `shade.preview.inputType` | warning |
| `generated/usdpreviewsurface-unknown-input.usda` | shade | `shade.preview.unknownInput` | warning |
| `generated/usdpreviewsurface-valid.usda` | — | (none — EXPECT-OK) | — |

`core.prim.name` is intentionally not covered by a `.usda` fixture: the USDA
parser rejects invalid prim names at parse time, so the rule is only reachable
for programmatically/crate-constructed layers. It is exercised in the unit test.

## Schema-driven generation (single source of truth)

`src/usd-preview-surface-schema.json` describes shader prim types and their
input name → value type. Two generators consume it:

- `scripts/gen-usd-preview-surface-inputs.py` → `src/usd-preview-surface-inputs.inc`
  — the validator's input-type table (included by `src/usd-validation.cc`).
  CTest `preview-surface-schema-sync` fails if the `.inc` is stale.
- `tests/usda/validation/gen_validation_fixtures.py` → `generated/` fixtures.
  The `-valid` fixture (every input at its schema type) doubles as a runtime
  drift detector: if the schema and the compiled table disagree it stops being
  clean and `validation-suite-test` fails.

```bash
# After editing src/usd-preview-surface-schema.json, regenerate both:
python3 scripts/gen-usd-preview-surface-inputs.py
python3 tests/usda/validation/gen_validation_fixtures.py
```

To extend coverage, add a shader type (and its inputs) to the schema JSON and
regenerate. The validator currently only checks `UsdPreviewSurface`; to validate
a new shader type, add a matching lookup in `src/usd-validation.cc`.

## Running directly

```bash
# Core only
./build/tusdcat --validate     tests/usda/validation/invalid/bad-meters-per-unit.usda
# All groups (core + geom + shade)
./build/tusdcat --validate-all tests/usda/validation/invalid/nested-gprim.usda
./build/tusdcat --validate-all tests/usda/validation/valid/clean.usda   # OK
```
