# MaterialX NodeGraph Optimization

This document describes the MaterialX NodeGraph optimization system in TinyUSDZ's JavaScript implementation.

## Overview

The NodeGraph optimizer analyzes and simplifies MaterialX node graphs exported from tools like Blender. It detects common patterns that can be reduced to simpler operations, removes identity operations, and eliminates dead code.

**Location:** `web/js/src/tinyusdz/TinyUSDZMaterialX.js`

## API

### optimizeNodeGraph(nodeGraph, level)

Optimizes a MaterialX NodeGraph by detecting and simplifying common patterns.

```javascript
import { optimizeNodeGraph, NodeGraphOptimizationLevel } from 'tinyusdz/TinyUSDZMaterialX.js';

const optimized = optimizeNodeGraph(material.openPBR.nodeGraph, NodeGraphOptimizationLevel.STANDARD);

console.log(optimized.optimizationInfo);
// {
//   patternsApplied: ['invert', 'brightness_contrast'],
//   identitiesRemoved: 3,
//   nodesRemoved: 5,
//   originalNodeCount: 12,
//   optimizedNodeCount: 7
// }
```

### analyzeNodeGraph(nodeGraph)

Analyzes a NodeGraph and returns optimization opportunities without applying them.

```javascript
import { analyzeNodeGraph } from 'tinyusdz/TinyUSDZMaterialX.js';

const analysis = analyzeNodeGraph(material.openPBR.nodeGraph);
console.log(analysis.potentialReduction); // e.g., "41.7%"
```

## Optimization Levels

| Level | Name | Description |
|-------|------|-------------|
| 0 | `NONE` | No optimization - pass through unchanged |
| 1 | `BASIC` | Remove identity operations only |
| 2 | `STANDARD` | Pattern detection + identity removal (recommended) |
| 3 | `AGGRESSIVE` | All optimizations + constant folding |

## Pattern Categories

### 1. Blender-Specific Patterns

These patterns are commonly generated by Blender's MaterialX exporter.

#### Invert Pattern
**Blender Node:** Invert

**Original graph:**
```
constant([1,1,1]) ─┐
                   ├─► subtract ─┐
input_color ───────┘             ├─► mix ─► output
input_color ─────────────────────┘
```

**Optimized:**
```
input_color ─► invert ─► output
```

#### Brightness/Contrast Pattern
**Blender Node:** Brightness/Contrast

**Original graph:**
```
input ─► multiply(contrast) ─► add(brightness) ─► subtract ─► max([0,0,0]) ─► output
```

**Optimized:**
```
input ─► brightness_contrast(brightness, contrast) ─► output
```

#### HSV Adjust Pattern
**Blender Node:** Hue/Saturation/Value

**Original graph:**
```
hue_value ────┐
sat_value ────┼─► combine3 ─┐
val_value ────┘             ├─► hsvadjust ─► output
input_color ────────────────┘
```

**Optimized:**
```
input_color ─► hsv_adjust(hue, saturation, value) ─► output
```

### 2. Extract/Combine Channel Patterns

#### Swizzle Pattern
Detects channel reordering via extract/combine.

**Original:**
```
input ─► extract(R) ─┐
input ─► extract(G) ─┼─► combine3(B,G,R) ─► output
input ─► extract(B) ─┘
```

**Detection:** Marks as swizzle "BGR" for shader optimization.

#### Channel to Grayscale
Detects single channel duplication.

**Original:**
```
input ─► extract(R) ─┬─► combine3(R,R,R) ─► output
                     ├─┘
                     └─┘
```

**Detection:** Marks as grayscale from channel R.

#### Separate/Combine Passthrough
Detects identity separate→combine chains.

**Original:**
```
input ─► separate(R,G,B) ─► combine(R,G,B) ─► output
```

**Optimized:**
```
input ─► output  (passthrough)
```

#### Single Channel Modification
Detects operations on a single channel.

**Original:**
```
input ─► extract(R) ─► invert ─┐
input ─► extract(G) ───────────┼─► combine3 ─► output
input ─► extract(B) ───────────┘
```

**Detection:** Marks as single channel R modification.

### 3. Math Operation Patterns

#### Add/Subtract Inverse
`a + b - b = a`

**Original:**
```
input ─► add(0.5) ─► subtract(0.5) ─► output
```

**Optimized:**
```
input ─► output  (passthrough)
```

#### Multiply/Divide Inverse
`a * b / b = a`

**Original:**
```
input ─► multiply(2.0) ─► divide(2.0) ─► output
```

**Optimized:**
```
input ─► output  (passthrough)
```

#### Idempotent Chain
`clamp(clamp(x)) = clamp(x)`, `normalize(normalize(x)) = normalize(x)`

**Original:**
```
input ─► normalize ─► normalize ─► normalize ─► output
```

**Optimized:**
```
input ─► normalize ─► output
```

### 4. Conversion Patterns

#### Convert Roundtrip
`color3_to_vector3(vector3_to_color3(x)) = x`

**Original:**
```
input ─► convert(color3→vector3) ─► convert(vector3→color3) ─► output
```

**Optimized:**
```
input ─► output  (passthrough)
```

#### Colorspace Roundtrip
`srgb_to_linear(linear_to_srgb(x)) = x`

**Original:**
```
input ─► srgb_to_linear ─► linear_to_srgb ─► output
```

**Optimized:**
```
input ─► output  (passthrough)
```

#### Chained Normalize
Multiple normalize operations reduced to one.

**Original:**
```
input ─► normalize ─► normalize ─► ... ─► output
```

**Optimized:**
```
input ─► normalize ─► output
```

### 5. Identity Operations

Operations with neutral values are removed.

| Operation | Identity Value | Removal |
|-----------|---------------|---------|
| `multiply` | `1.0` or `[1,1,1]` | Pass through input |
| `add` | `0.0` or `[0,0,0]` | Pass through input |
| `subtract` | `0.0` or `[0,0,0]` | Pass through input |
| `divide` | `1.0` or `[1,1,1]` | Pass through input |
| `power` | `1.0` | Pass through input |
| `mix` | `factor=0` | Pass through `bg` |
| `mix` | `factor=1` | Pass through `fg` |

### 6. Miscellaneous Patterns

#### Mix Same Inputs
`mix(a, a, factor) = a`

**Original:**
```
input ─┬─► mix(factor) ─► output
       └─┘
```

**Optimized:**
```
input ─► output  (passthrough)
```

#### Clamp Pattern
Detects if clamp is already bounded by previous operations.

#### Geometry Setup Pattern
Detects common geometry node setups (position, normal, tangent with space transforms).

#### Luminance Extract
Detects luminance calculation patterns.

## Chain Detection

The optimizer can detect chains of operations up to a configurable depth (default: 16 nodes).

**Example - Inverse Chain:**
```
input ─► invert ─► invert ─► invert ─► invert ─► output
```

**Analysis:**
- Chain length: 4 (even)
- Result: Passthrough (even number of inversions cancel out)

**Example - Separate/Combine Chain:**
```
input ─► separate ─► combine ─► separate ─► combine ─► output
```

**Optimized:**
```
input ─► output  (passthrough)
```

## Usage Examples

### Basic Usage

```javascript
import { TinyUSDZLoader } from 'tinyusdz/TinyUSDZLoader.js';
import { optimizeNodeGraph, NodeGraphOptimizationLevel } from 'tinyusdz/TinyUSDZMaterialX.js';

const loader = new TinyUSDZLoader();
await loader.init();

const usd = await loader.loadAsync('scene.usdz');
const numMaterials = usd.numMaterials();

for (let i = 0; i < numMaterials; i++) {
    const result = usd.getMaterialWithFormat(i, 'json');
    const material = JSON.parse(result.data);

    if (material.openPBR?.nodeGraph) {
        // Optimize the node graph
        const optimized = optimizeNodeGraph(
            material.openPBR.nodeGraph,
            NodeGraphOptimizationLevel.STANDARD
        );

        console.log(`Material: ${material.name}`);
        console.log(`  Original nodes: ${optimized.optimizationInfo.originalNodeCount}`);
        console.log(`  Optimized nodes: ${optimized.optimizationInfo.optimizedNodeCount}`);
        console.log(`  Patterns applied: ${optimized.optimizationInfo.patternsApplied.join(', ')}`);
    }
}
```

### Analysis Only

```javascript
import { analyzeNodeGraph } from 'tinyusdz/TinyUSDZMaterialX.js';

const analysis = analyzeNodeGraph(material.openPBR.nodeGraph);

console.log('Optimization Analysis:');
console.log(`  Total nodes: ${analysis.totalNodes}`);
console.log(`  Potential reduction: ${analysis.potentialReduction}`);
console.log(`  Identity operations: ${analysis.identities.length}`);

if (analysis.patterns.invert.length > 0) {
    console.log(`  Invert patterns found: ${analysis.patterns.invert.length}`);
}
if (analysis.patterns.brightnessContrast.length > 0) {
    console.log(`  Brightness/Contrast patterns: ${analysis.patterns.brightnessContrast.length}`);
}
```

### With WebGL2 Material Creation

```javascript
import { createOpenPBRMaterial } from 'tinyusdz/TinyUSDZOpenPBR_WebGL.js';
import { optimizeNodeGraph, NodeGraphOptimizationLevel } from 'tinyusdz/TinyUSDZMaterialX.js';

// Get material data from USD
const matData = JSON.parse(usd.getMaterialWithFormat(0, 'json').data);

// Optimize node graph before material creation
let nodeGraph = matData.openPBR?.nodeGraph;
if (nodeGraph) {
    nodeGraph = optimizeNodeGraph(nodeGraph, NodeGraphOptimizationLevel.STANDARD);
}

// Create Three.js material with optimized graph
const material = createOpenPBRMaterial({
    base_color: matData.openPBR?.base_color || [0.8, 0.8, 0.8],
    base_metalness: matData.openPBR?.base_metalness ?? 0,
    specular_roughness: matData.openPBR?.specular_roughness ?? 0.5,
    nodeGraph: nodeGraph
});
```

## Performance Considerations

1. **Run optimization once** at load time, not per frame
2. **Use STANDARD level** for best balance of speed and reduction
3. **AGGRESSIVE level** includes constant folding which may take longer
4. **Cache optimized graphs** when reloading the same materials

## Supported MaterialX Node Types

The optimizer recognizes these node categories:

**Math:** add, subtract, multiply, divide, power, min, max, clamp, mix
**Color:** invert, hsvadjust, brightness_contrast, luminance
**Channel:** extract, combine3, separate3, swizzle
**Convert:** convert (color3↔vector3), srgb_to_linear, linear_to_srgb
**Vector:** normalize, magnitude, dotproduct
**Geometry:** position, normal, tangent, texcoord

## Blender Export Notes

When exporting from Blender with MaterialX:

1. Enable "Generate MaterialX Network" in USD export options
2. Blender converts its shader nodes to MaterialX equivalents
3. Some conversions create verbose node chains (e.g., Invert → subtract + mix)
4. The optimizer simplifies these back to semantic equivalents

## Mesh Attribute Resolution (UVs and Normals)

This section describes how TinyUSDZ's Tydra resolves UV coordinates and normals from USD meshes during `ConvertMesh()`, and how this aligns with OpenUSD's MaterialX integration.

### UV Coordinates (Texcoords)

**Primvar lookup:** `primvars:st` (configurable via `MeshConverterConfig::default_texcoords_primvar_name`, default `"st"`)

Tydra resolves texcoords through two paths depending on whether materials are bound:

#### Path 1: No materials bound

When no materials are assigned to the mesh, Tydra directly checks for the default texcoord primvar:

```
mesh.has_primvar("st") → GetTextureCoordinate() → dst.texcoords[0]
```

#### Path 2: Materials bound

When materials ARE assigned, Tydra first tries to extract UV names from shader connections via `ListUVNames()`, which walks through shader parameters and finds UV primvar names referenced by texture nodes.

**Implicit fallback:** If no UV names are found via shader connections (e.g. MaterialX materials with procedural nodes but no explicit texture connections), Tydra falls back to checking the default texcoord primvar on the mesh:

```
ListUVNames(material) → uvname_map
  ├─ (has UV names) → GetTextureCoordinate(uvname) → dst.texcoords[slotId]
  └─ (empty)        → mesh.has_primvar("st") → dst.texcoords[0]  (fallback)
```

This fallback mirrors OpenUSD's implicit `defaultgeomprop="UV0"` → `primvars:st` mapping, where MaterialX's `UV0` is replaced with `UsdUtilsGetPrimaryUVSetName()` (returns `"st"` by default).

**Reference:** `src/tydra/render-data.cc` lines ~4255-4360

#### Tangent/Binormal computation

Tangent computation requires texcoords. If `dst.texcoords[0]` is not available, the computation is skipped with a warning instead of failing the entire mesh conversion:

```cpp
if (!dst.texcoords.count(0)) {
    PUSH_WARN("texcoord is not assigned to the mesh. "
              "Skipping tangent/binormal computation.");
}
```

### Normals

**Primvar lookup order:**
1. `primvars:normals` — checked first via `mesh.has_primvar("normals")`
2. `normals` (legacy attribute) — checked second via `mesh.normals.authored()`
3. Auto-compute — smooth normals computed if neither source exists

```
mesh.has_primvar("normals")     → GetGeomPrimvar() → dst.normals   (1. primvar)
  └─ mesh.normals.authored()    → EvaluateTyped..() → dst.normals  (2. legacy)
       └─ (neither)             → ComputeNormals()  → dst.normals  (3. auto)
```

**Key difference from UVs:** Normals are loaded **unconditionally** from mesh geometry — they do not depend on material bindings. This matches OpenUSD's behavior where mesh geometric normals are implicitly available to all MaterialX shaders through the rendering backend (via `HdGet_normal()` in Hydra).

There is no `defaultgeomprop` mechanism for normals in MaterialX (unlike UV0 for texcoords). Normal maps are explicitly connected to shader inputs (e.g. `inputs:normal` or `geometry_normal` in OpenPBR), while the underlying mesh normals are always available automatically.

**Interpolation:** The interpolation mode from USD (Varying, Constant, Uniform, Vertex, FaceVarying) is preserved. For single-indexable meshes with facevarying normals, Tydra attempts to convert to vertex variability via `TryConvertFacevaryingToVertex()`.

**Auto-computation** is triggered when:
- `MeshConverterConfig::compute_normals` is true (default) AND normals are missing
- OR `compute_tangents_and_binormals` is true AND normals are missing (tangent computation needs normals)

**Reference:** `src/tydra/render-data.cc` lines ~4480-4558 (loading), ~5299-5339 (auto-compute)

### Comparison with OpenUSD

| Attribute | OpenUSD | TinyUSDZ Tydra |
|-----------|---------|----------------|
| **UV primvar** | `defaultgeomprop="UV0"` → `UsdUtilsGetPrimaryUVSetName()` → `"st"` | `default_texcoords_primvar_name` → `"st"` (configurable) |
| **UV env override** | `USDMTLX_PRIMARY_UV_NAME` | `MeshConverterConfig::default_texcoords_primvar_name` |
| **UV implicit binding** | Via `defaultgeomprop` in MaterialX node definitions | Fallback when no UV names from shader connections |
| **Normal primvar** | `primvars:normals`, then `normals` attribute | Same: `primvars:normals`, then `normals` (legacy) |
| **Normal binding** | Implicit — `HdGet_normal()` in Hydra shaders | Implicit — loaded unconditionally from mesh geometry |
| **Normal auto-compute** | Render delegate dependent | `ComputeNormals()` — smooth normals for shared vertices |
| **Normal map** | Connected via nodegraph → `inputs:normal` | Extracted via `ExtractMtlxNodeGraphInfo()` → `geometry_normal` |
